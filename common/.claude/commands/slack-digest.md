# Slack Digest

Збирає повідомлення зі Slack за вказаний період і створює структурований AI-дайджест українською.

**Використання:** `/slack-digest [--period 24h|2d|Xh] [--date DD.MM.YYYY] [--channels ch1,ch2]`

Параметри:
- `--period` — часове вікно від поточного моменту (напр. `24h`, `2d`, `48h`). За замовчуванням: `24h`
- `--date` — конкретна дата (весь день). Перекриває `--period`
- `--channels` — перелік каналів через кому (перекриває дефолтні канали з `.env`; PM DM виключається)

---

## Крок 1 — Парсинг аргументів

З `$ARGUMENTS` витягнути **тільки те що явно вказав користувач**:
- `--period VALUE` → передати у скрипт як `--period VALUE`
- `--date DD.MM.YYYY` → передати як `--date DD.MM.YYYY`
- `--channels ch1,ch2` → передати як `--channels ch1,ch2`

Якщо `--period` і `--date` відсутні — використати `--period 24h` за замовчуванням.

**ВАЖЛИВО:** Не додавати `--channels` самостійно. Якщо користувач не вказав `--channels` — не передавати цей параметр зовсім. Скрипт сам підхопить канали з `SLACK_DEFAULT_CHANNELS` у `.env` **і** включить DM з PM. Якщо передати `--channels` — DM з PM буде виключено автоматично.

## Крок 3 — AI-аналіз: семантична кластеризація + генерація дайджесту

Аналіз виконується у два проходи для кожного каналу.

### Прохід 1 — Семантична кластеризація

Перед генерацією DigestEntry прочитай усі повідомлення каналу (`channels[*].messages`) у хронологічному порядку та згрупуй їх у семантичні кластери.

**Кластер** — це група повідомлень що стосуються однієї теми або проблеми, незалежно від того чи вони знаходяться у треді чи йдуть послідовно в каналі.

Орієнтири для кластеризації:
- **Тред** — якщо повідомлення має `thread[]` → всі ці відповіді вже є частиною одного кластера разом з батьківським повідомленням
- **Послідовні повідомлення** — якщо кілька повідомлень у каналі обговорюють одну й ту саму тему (та сама фіча, баг, задача), вони утворюють один кластер навіть без треду
- **@згадки та відповіді** — якщо повідомлення явно звертається до попереднього (за іменем, цитатою або контекстом) — воно у тому ж кластері
- **Ключові слова** — повторення назв систем, тікетів, функцій, імен — ознака одного кластера
- **Різні теми одночасно** — якщо два менеджери паралельно обговорюють різні речі між їхніми повідомленнями немає змістовного зв'язку → різні кластери

Одиночне повідомлення без зв'язаних сусідів → окремий кластер з одного елемента.

### Прохід 2 — Генерація DigestEntry

Для кожного кластера сформувати один запис:

**Включати:**
- Кластери з будь-яким змістовним текстом

**Пропускати:**
- Кластери де всі повідомлення порожні або лише реакції та присутній `bot_id`
- Автоматичні CI/CD нотифікації без змістовного контексту

**Для кожного включеного кластера сформувати:**

- `channel_id` — взяти з `channels[*].id`
- `message_link` — побудувати для **першого повідомлення кластера** (найменший `ts`):
  `https://{SLACK_WORKSPACE_DOMAIN}.slack.com/archives/{channel_id}/p{ts без крапки}`
  (ts `1748050000.123456` → `p1748050000123456`)
- `summary` — стисло **українською**, 2–4 речення. Синтезувати суть усього обміну в кластері включно з тредами
- `status`:
  - `"bug"` — описує проблему, помилку, дефект, падіння
  - `"question"` — запитання без чіткої відповіді або відкрита дискусія
  - `"task"` — завдання, запит на дію, доручення
  - `"announcement"` — оголошення, інформування без дискусії
  - `"info"` — все інше: уточнення, підтвердження, нейтральний обмін
- `use_case` — одна фраза **українською** про функціональну область або контекст
- `resources` — масив посилань і ідентифікаторів зі всіх повідомлень кластера:
  - URL тікетів (JIRA, Shortcut, Linear тощо)
  - `files[*].permalink` — прикріплені файли та скріншоти
  - будь-які інші URL знайдені в тексті повідомлень

**Окремо для Loom та Fathom посилань:**

Якщо в тексті будь-якого повідомлення кластера є посилання на `loom.com` або `fathom.ai`:
1. Відвідати кожне посилання через WebFetch
2. Витягнути заголовок, опис та доступний текст (транскрипт якщо є на сторінці)
3. Використати знайдений контент для збагачення `summary` та уточнення `use_case`
4. Додати посилання до `resources`

Якщо сторінка недоступна або повернула порожній контент — просто додати посилання до `resources` без аналізу.

## Крок 4 — Запит шляху для збереження

Запитати у користувача:

> "Де зберегти JSON-дайджест? Натисніть Enter для поточної директорії (slack-digest-YYYY-MM-DD.json)"

Якщо користувач натискає Enter або залишає поле порожнім — використати `./slack-digest-YYYY-MM-DD.json` де дата відповідає сьогоднішній (або даті з `--date`).

---

## Крок 5 — Збереження JSON

Записати файл із масивом об'єктів:

```json
[
  {
    "channel_id": "C1234567890",
    "message_link": "https://mycompany.slack.com/archives/C1234567890/p1748050000123456",
    "summary": "Користувач повідомив про помилку при завантаженні документів у Firefox. Кілька менеджерів підтвердили відтворення. Проблема пов'язана з обробкою MIME-типів.",
    "status": "bug",
    "use_case": "Завантаження файлів",
    "resources": ["TICKET-4521", "https://sentry.io/issues/123"]
  }
]
```

Підтвердити: `Дайджест збережено: {шлях} ({N} записів)`
