# Slack Digest

Збирає повідомлення зі Slack за вказаний період і створює структурований AI-дайджест українською.

**Використання:** `/slack-digest [--period 24h|2d|Xh] [--date DD.MM.YYYY] [--channels ch1,ch2]`

Параметри:
- `--period` — часове вікно від поточного моменту (напр. `24h`, `2d`, `48h`). За замовчуванням: `24h`
- `--date` — конкретна дата (весь день). Перекриває `--period`
- `--channels` — перелік каналів через кому (перекриває дефолтні канали з `.env`; DM з PM виключається)

---

## Крок 1 — Парсинг аргументів

З `$ARGUMENTS` витягнути **тільки те що явно вказав користувач**:
- `--period VALUE` → передати у скрипт як `--period VALUE`
- `--date DD.MM.YYYY` → передати як `--date DD.MM.YYYY`
- `--channels ch1,ch2` → передати як `--channels ch1,ch2`

Якщо `--period` і `--date` відсутні — використати `--period 24h` за замовчуванням.

**ВАЖЛИВО:** Не додавати `--channels` самостійно. Якщо користувач не вказав `--channels` — не передавати цей параметр зовсім. Скрипт сам підхопить канали з `SLACK_DEFAULT_CHANNELS` у `.env` **і** включить DM з PM. Якщо передати `--channels` — DM з PM буде виключено автоматично.

Перед запуском вивести одним рядком підтвердження:
> Завантажую: [24h / дата DD.MM.YYYY], канали: [список або "дефолтні + DM з PM"]

## Крок 2 — Завантаження даних зі Slack

Запустити скрипт **без зміни директорії** — `--prefix` вказує де знаходиться пакет, але CWD залишається у проекті:

**PowerShell:**
```powershell
npm run --prefix $env:AI_CONFIGS_DIR\automation slack-digest-fetch -- [PARSED ARGS]
```

**bash / macOS:**
```bash
npm run --prefix "$AI_CONFIGS_DIR/automation" slack-digest-fetch -- [PARSED ARGS]
```

Скрипт автоматично зчитає `SLACK_DIGEST_OUTPUT_DIR` з `.env` поточного проекту (якщо є) і збереже файли туди. Якщо змінна не задана — збереже у поточній директорії.

Дочекатися виводу JSON у stdout. У разі помилки — показати stderr і зупинитись.

Скрипт виводить JSON з такою структурою верхнього рівня:
```json
{
  "workspace_domain": "mycompany",
  "digest_name": "slack-digest-2026-05-24_09-00--2026-05-25_09-00",
  "period": { "from": 1748..., "to": 1748... },
  "channels": [...]
}
```

Кожне повідомлення вже містить готове поле `message_link`.

## Крок 2.5 — Попередній збір контенту з медіа

**До початку аналізу** — опрацювати всі медіа у завантаженому JSON.

### Відео (loom.com, fathom.ai)

Знайти всі посилання на `loom.com` та `fathom.ai` у `channels[*].messages[*].text` та `channels[*].messages[*].thread[*].text`.

Для кожного посилання — викликати WebFetch на URL, зберегти заголовок, опис, транскрипт. Прив'язати до `ts` повідомлення.

### Зображення (скріншоти)

Знайти всі файли з `local_path` у `channels[*].messages[*].files` та `channels[*].messages[*].thread[*].files`.

Для кожного файлу з `local_path` — викликати **Read** на цей шлях. Claude побачить зображення і може описати його зміст. Зберегти опис і прив'язати до `ts` повідомлення.

Якщо `local_path` відсутній (файл не є зображенням або завантаження не вдалось) — використати `name` файлу та контекст із тексту повідомлення.

Цей крок виконується **завжди**. Зібраний контент використовується у Кроці 3 для збагачення `summary`, `use_case` та `repro_steps`.

## Крок 3 — AI-аналіз: семантична кластеризація + генерація дайджесту

Аналіз виконується у два проходи для кожного каналу.

### Прохід 1 — Семантична кластеризація

Прочитай усі повідомлення каналу (`channels[*].messages`) у хронологічному порядку та згрупуй їх у семантичні кластери.

**Кластер** — це група повідомлень що стосуються однієї теми або проблеми.

Орієнтири для кластеризації:
- **Тред** — якщо повідомлення має `thread[]` → всі відповіді вже є частиною одного кластера разом з батьківським повідомленням
- **Послідовні повідомлення** — якщо кілька повідомлень обговорюють одну й ту саму тему, вони утворюють один кластер навіть без треду
- **@згадки та відповіді** — якщо повідомлення явно звертається до попереднього — воно у тому ж кластері
- **Ключові слова** — повторення назв систем, тікетів, функцій, імен — ознака одного кластера
- **Різні теми** — якщо повідомлення не мають змістовного зв'язку → різні кластери

Одиночне повідомлення без зв'язаних сусідів → окремий кластер з одного елемента.

### Прохід 2 — Генерація DigestEntry

Для кожного кластера сформувати один запис.

**Включати:** кластери з будь-яким змістовним текстом.

**Пропускати:** кластери де всі повідомлення порожні або складаються лише з реакцій без тексту.

**Для кожного включеного кластера:**

- `channel_id` — взяти з `channels[*].id`
- `message_link` — взяти з поля `message_link` **першого повідомлення кластера** (найменший `ts`). НЕ будувати вручну.
- `summary` — стисло **українською**, 2–4 речення. Синтезувати суть усього обміну включно з тредами та медіа-контентом з Кроку 2.5
- `participants` — масив унікальних `user_name` з усіх повідомлень і тредів кластера. Виключити `"unknown"`. Взяти топ-3 найактивніших (хто найбільше писав у кластері)
- `status` — визначати з урахуванням реакцій на повідомленнях (поле `reactions`):

  | Значення | Коли застосовувати | Реакції-підказки |
  |---|---|---|
  | `"bug"` | Описує помилку, дефект, падіння. *Напр.: "після оновлення не відкривається сторінка"* | 🚨 `rotating_light`, 🔥 `fire` |
  | `"task"` | Доручення або запит на новий функціонал. *Напр.: "треба додати фільтр по даті"* | |
  | `"question"` | Відкрите запитання **без** повної відповіді у кластері. Якщо відповідь є → це `"info"` | |
  | `"announcement"` | Інформування без дискусії та без очікуваних дій. *Напр.: "деплой о 18:00"* | |
  | `"info"` | Завершений обмін, уточнення, підтвердження, питання з відповіддю | ✅ `white_check_mark`, `check_mark` |

  Якщо на повідомленні є ✅ — навіть якщо зміст схожий на `"bug"` чи `"task"`, розглянь чи проблема вже вирішена і використай `"info"`.

- `use_case` — одна фраза **українською** про функціональну область або контекст
- `resources` — унікальний масив посилань зі всіх повідомлень кластера (дублікати видалити):
  - Для файлів: якщо є `files[*].local_path` — **використовувати його** (локальний файл, доступний без авторизації); інакше — `files[*].permalink`
  - URL тікетів (JIRA, Shortcut, Linear тощо)
  - Loom/Fathom посилання
  - будь-які інші URL з тексту повідомлень
- `repro_steps` — **заповнювати тільки для `status: "bug"` або `status: "task"`**:

  Проаналізуй текст усіх повідомлень і тредів кластера + опис зображень та відео з Кроку 2.5:

  ```json
  {
    "environment": "Firefox 124, Windows 10 — якщо згадується; null якщо невідомо",
    "steps": [
      "1. Перейти на сторінку X",
      "2. Натиснути кнопку Y",
      "3. ..."
    ],
    "expected": "що мало відбутись",
    "actual": "що відбулось насправді / текст помилки",
    "code_location": "src/upload/handler.ts — якщо є stack trace або назви файлів у повідомленнях; 'потрібен доступ до кодової бази' якщо невідомо"
  }
  ```

  - `environment` — шукати у тексті: назву браузера, ОС, пристрою, ролі користувача
  - `steps` — реконструювати з опису дій у повідомленнях та зображеннях
  - `expected` / `actual` — шукати формулювання "мало бути", "але сталося", текст помилки
  - `code_location` — витягти з stack trace, назв файлів, функцій якщо є; інакше `"потрібен доступ до кодової бази"`
  - Якщо кроків недостатньо → `"steps": ["Деталі не вказані — перейти за message_link"]`

## Крок 4 — Збереження JSON

Взяти `digest_name` з JSON-результату скрипту (поле верхнього рівня).

Зберегти файл у директорії де була запущена команда (`$outDir`):
```
{$outDir}/{digest_name}.json
```

Приклад: `./slack-digest-2026-05-24_09-00--2026-05-25_09-00.json`

Якщо скрипт завантажував зображення — вони вже знаходяться у `{$outDir}/{digest_name}/` (папка з тією ж назвою що і JSON).

**Формат JSON-файлу:**

```json
[
  {
    "channel_id": "C1234567890",
    "message_link": "https://mycompany.slack.com/archives/C1234567890/p1748050000123456",
    "summary": "Користувач повідомив про помилку при завантаженні документів у Firefox. Кілька менеджерів підтвердили відтворення. Проблема пов'язана з обробкою MIME-типів.",
    "status": "bug",
    "use_case": "Завантаження файлів",
    "participants": ["anna.koval", "petro.sydorenko"],
    "resources": ["TICKET-4521", "https://sentry.io/issues/123"],
    "repro_steps": {
      "environment": "Firefox 124, Windows 10",
      "steps": ["1. Відкрити сторінку завантаження документів", "2. Обрати PDF файл", "3. Натиснути Upload"],
      "expected": "Файл завантажується успішно",
      "actual": "Помилка: MIME type not supported",
      "code_location": "потрібен доступ до кодової бази"
    }
  }
]
```

Підтвердити: `Дайджест збережено: {шлях} ({N} записів)`
