# Shortcut Epic

Аналізує епік у Shortcut і пропонує набір нових сторі, які логічно покривають його скоуп, через Shortcut MCP. **Нічого не створюється у Shortcut без явного підтвердження.**

**Використання:** `/shortcut-epic [Epic ID або URL]`

---

## Крок 0 — Визначення епіка

З `$ARGUMENTS` витягнути ідентифікатор епіка:
- Якщо передано число — це Epic ID.
- Якщо передано URL (напр. `https://app.shortcut.com/.../epic/12345/...`) — витягнути числовий ID зі шляху.

Якщо аргумент не передано:

> "Вкажи ID або URL епіка в Shortcut."

Дочекатися відповіді перед продовженням.

---

## Крок 1 — Перевірка доступу до Shortcut MCP

Переконатися, що доступні інструменти Shortcut MCP (`mcp__shortcut__*`). Якщо їх немає:

> "Shortcut MCP-сервер недоступний. Перевір що:
> 1. У `automation/.env` заданий `SHORTCUT_API_TOKEN`
> 2. Запущено setup-скрипт для цього проєкту (щоб згенерувати `.mcp.json`)
> 3. Claude Code перезапущено, а `/mcp` показує `shortcut` як підключений"

І зупинитись.

---

## Крок 2 — Збір інформації

Через інструменти Shortcut MCP отримати по епіку:
- **Title** і **description**
- **Існуючі сторі** в епіку — прочитати title/description кожної, щоб розуміти що вже покрито і не дублювати.

Опрацювати вкладення та матеріали (та сама логіка, що й у `/shortcut-story`):
- **Зображення** — описати контекстно.
- **PDF / Word** — прочитати текст.
- **Посилання / External Links** — відкрити (WebFetch).
- **Відео** (Loom, Fathom) — шукати транскрипт у description/коментарях; якщо немає — спробувати через URL.

**Якщо будь-яке вкладення, посилання чи відео не вдається прочитати** — не пропускати мовчки, а попросити користувача надати контент:

> "Не вдалося прочитати \<що саме\> (\<причина\>). Можеш надати зміст текстом, скріншотом або коротким описом?"

Дочекатися, поки матимеш достатньо контексту.

---

## Крок 3 — Аналіз контексту проєкту

Перш ніж пропонувати сторі — зрозуміти наявну архітектуру, щоб сторі лягали в неї й не дублювали вже реалізоване.

1. **Знайти project map воркспейсу.** Знайти CLAUDE.md рівня воркспейсу (той, що містить «Project map» / опис відповідальності репозиторіїв) — перевірити поточну директорію та її батьківську (`./CLAUDE.md`, `../CLAUDE.md`). Зрозуміти які репозиторії існують і за що відповідають (фронтенд / бекенд).

2. **Визначити релевантний проєкт(и).** Авто з поточної директорії; якщо неясно або це корінь воркспейсу — показати project map і запитати, яких проєктів стосується епік (може бути кілька).

3. **Прочитати контекст:** `CLAUDE.md` + `.claude/rules/*.md` релевантного(их) проєкту(ів) (стек, патерни, конвенції).

4. **Точковий аналіз наявного.** За ключовими словами епіка зробити `Grep`/`Glob`, щоб побачити що вже реалізовано у відповідних репозиторіях. Дотичні файли читати точково за потреби. Бекенд — за project map; якщо репо недоступне, позначити, що його не аналізовано.

Висновки використати в Кроці 4, щоб не пропонувати вже зроблене і формулювати сторі під наявний стек.

---

## Крок 4 — Генерація нових сторій

На основі скоупу епіка **та аналізу контексту (Крок 3)** згенерувати набір нових сторій:
- Поля кожної: `name` (title) і `description`.
- Сторі мають **логічно покривати весь скоуп епіка** і лягати в наявну архітектуру (стек, патерни з Кроку 3).
- **Не дублювати** вже існуючі сторі (Крок 2) і вже реалізований код. Якщо існуючі сторі чи наявний код покривають частину скоупу — врахувати це і запропонувати лише те, чого бракує.

---

## Крок 5 — Обов'язковий review перед створенням

Показати повний список запропонованих сторій:

```
Епік #<id>: <title>

Сторі 1: <title>
  Опис: <description>

Сторі 2: <title>
  Опис: <description>
```

Запитати:

> "Створити ці сторі в епіку? (yes / no / edit N)"

Обробити відповідь:
- `yes` — перейти до Кроку 6 і створити всі сторі.
- `no` — скасувати, нічого не створювати.
- `edit N` — показати сторі №N детально, дати користувачу внести зміни, потім показати оновлений список і запитати підтвердження знову.

**Без явного `yes` нічого не створювати у Shortcut.**

---

## Крок 6 — Створення сторій

Тільки після `yes` — для кожної сторі через інструменти Shortcut MCP створити сторі з полями `name` і `description`, прив'язану до цього епіка (`epic_id`).

У підсумку вивести список створених сторій з їхніми ID/посиланнями:

```
Створено сторій в епіку #<id>: <count>
- #<id> <title>
- #<id> <title>
```
